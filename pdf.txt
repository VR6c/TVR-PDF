2. PROJECT OVERVIEW

Project Name: TVR-PDF

Product Type: Progressive Web Application (PWA)

Core Concept:

Build a premium, modern, browser-based PDF reader and editor inspired by Adobe Acrobat and professional document productivity applications.

The application must allow users to read, annotate, sign, organize, modify, and export PDF documents without registration, subscriptions, cloud uploads, or backend processing.

Core Principles

100% client-side document processing.

Zero authentication and registration.

No traditional backend.

No cloud document storage.

Offline-first architecture.

Privacy-first document handling.

High-performance PDF rendering.

Professional and intuitive UI/UX.

Responsive desktop, tablet, and mobile experience.

Maintainable and scalable architecture.

IMPORTANT:

Do not introduce a backend, database server, authentication service, cloud file storage, or server-side PDF processing.

All document operations must happen locally on the user's device.

Static hosting is permitted for delivering application assets and updates.

9. CRITICAL SECURITY REQUIREMENTS

Security and privacy are core product requirements.

Zero Data Exfiltration

PDF files, document names, annotation data, signatures, and passwords must never be transmitted over the network.

No:

Cloud uploads.

Remote document APIs.

Analytics containing document data.

Third-party document processing.

Remote signature storage.

External telemetry containing sensitive information.

Content Security Policy

Configure an appropriate strict Content Security Policy.

Restrict:

Script sources.

Connect sources.

Object sources.

Frame sources.

Worker sources.

Account for required PDF.js workers, WASM execution, and application asset loading without unnecessarily weakening security.

Permanent Redaction

THIS IS A CRITICAL SECURITY FEATURE.

A black rectangle over text is NOT permanent redaction.

Implement a redaction pipeline that:

Selects the target region.

Identifies underlying PDF text and graphics.

Removes affected content rather than merely covering it.

Sanitizes intersecting image content when possible.

Rebuilds the affected page content.

Exports a sanitized PDF.

Verifies that the removed information cannot be recovered through text extraction or normal PDF object inspection.

If a PDF structure cannot be safely redacted, fail safely and clearly explain the limitation.

Never advertise a visual overlay as secure permanent redaction.

Local Data Wipe

Provide a Clear All Local Data feature.

It must remove:

Stored documents.

Drafts.

Annotations.

Saved signatures.

Related metadata.

Require confirmation before deletion.
